Todas las herramientas aceptan nombres o ids (`app: "web"` o el UUID), y `project` es opcional cuando la cuenta tiene un solo proyecto. Sin sufijo, `project` es producción; `project: "tienda.staging"` apunta al [ambiente](/cuenta/ambientes) staging. Los errores vuelven con la acción a seguir, para que el agente se pueda corregir solo.

:::note[Convenciones]
- **Nombres**: entre 3 y 63 caracteres, minúsculas, números y guiones.
- **`kind`**: `postgres`, `redis`, `bucket` o `email`.
- Las herramientas de lectura están marcadas como `readOnly`; las de borrado, como `destructive`.
:::

## Conexión

### `login`

Conecta el agente a la cuenta cuando se usa el plugin de Claude Code. Sin `code`, devuelve un enlace para que la persona autorice en olimpia.dev; con `code`, canjea el código de 8 caracteres que recibió. También informa qué cuenta está conectada.

| Parámetro | Tipo | |
| --- | --- | --- |
| `code` | string | Opcional. El código de conexión. |

## Descubrir

### `list_projects`

Lista los proyectos con sus ambientes (producción primero), y de cada ambiente la cantidad de recursos y la salud de sus apps. Sin parámetros.

### `get_project`

Resumen de un proyecto: cada app (estado, URL, origen), Postgres, Redis y bucket, con enlaces a la consola. Es el mejor punto de partida para descubrir nombres.

| Parámetro | Tipo | |
| --- | --- | --- |
| `project` | string | Opcional. |

### `get_app`

Detalle de una app: URL, origen, configuración de build, bases conectadas, dominios y últimos deploys.

| Parámetro | Tipo | |
| --- | --- | --- |
| `app` | string | Nombre o id. |

### `get_usage`

Uso actual de un proyecto: apps online y construyendo, objetos y bytes en buckets, dominios de email y destinatarios enviados en el mes, contra el cupo mensual. Para estimar cuánto cuesta, usá [`estimate_cost`](#costos).

## Desplegar

### `create_app`

Crea una app. Con `source=upload` (por defecto) la respuesta trae el comando para subir la carpeta local; después hay que llamar a `deploy` con el `source_key`.

| Parámetro | Tipo | |
| --- | --- | --- |
| `name` | string | Nombre de la app, también usado como subdominio. |
| `source` | `upload` \| `github` \| `image` | Opcional. `upload` por defecto. |
| `repo` | string | Para `github`: `owner/name`. |
| `branch` | string | Para `github`: rama a desplegar. Cada push redespliega. |
| `image` | string | Para `image`: por ejemplo `nginx:1.29`. |
| `root_dir` | string | Subcarpeta a construir, para monorepos. |
| `dockerfile` | string | Ruta al Dockerfile relativa a `root_dir`. Sin ella, Railpack detecta el stack. |
| `builder` | `default` \| `acropolis` | Opcional. `default` usa el Dockerfile si hay uno y, si no, Railpack. `acropolis` construye con [Acropolis](/productos/acropolis), que ignora el Dockerfile; si no puede construir la app, sigue con el builder por defecto. |
| `port` | number | Puerto en el que escucha la app (3000 por defecto). |
| `env` | object | Variables a cargar antes del primer build. |
| `server` | string | Avanzado, normalmente se omite. Servidor del proyecto; solo cambia si todavía no tiene apps ni bases. |

### `get_upload_url`

Devuelve una URL de subida nueva (vale 15 minutos) y el comando para subir la carpeta de una app con `source=upload`.

### `deploy`

Construye y despliega una app. Espera hasta `wait_seconds` y devuelve el estado, con el final del log si falló.

| Parámetro | Tipo | |
| --- | --- | --- |
| `app` | string | Nombre o id. |
| `source_key` | string | Para `upload`: la clave de la subida. Sin ella, reconstruye la última subida. |
| `message` | string | Descripción corta del cambio, visible en el historial. |
| `wait_seconds` | number | 0 a 50, 45 por defecto. |

### `get_deployment`

Estado de un deploy (el último por defecto), opcionalmente esperando mientras corre. Incluye las últimas líneas del log cuando falló o está construyendo.

| Parámetro | Tipo | |
| --- | --- | --- |
| `app` | string | Nombre o id. |
| `deployment` | string | Opcional. Id del deploy. |
| `wait_seconds` | number | 0 a 50, 0 por defecto. |

### `rollback`

Vuelve a un deploy anterior que haya estado online, reusando su imagen sin build.

| Parámetro | Tipo | |
| --- | --- | --- |
| `app` | string | Nombre o id. |
| `deployment` | string | Id del deploy (ver `get_app`). |

### `cancel_deployment`

Cancela un deploy en cola o construyendo (el último por defecto).

## Templates

### `list_templates`

Lista o busca los templates que se pueden deployar, con `id`, `name`, `description`, `image`, `postgres` y `redis` (qué bases crea `deploy_template`).

| Parámetro | Tipo | |
| --- | --- | --- |
| `search` | string | Opcional. Palabras a buscar en el nombre, la descripción y las etiquetas. Sin búsqueda, lista todo el catálogo. |

### `deploy_template`

Despliega un template como una app nueva: crea la base Postgres y el Redis si el template los necesita, genera los secretos y las URLs como variables (se ven con `get_env`) y arranca el primer deploy. Ver [Templates](/apps/templates).

| Parámetro | Tipo | |
| --- | --- | --- |
| `template` | string | Id del template, por ejemplo `n8n`. |
| `name` | string | Opcional. Nombre de la app y subdominio; también el de sus bases. El id del template por defecto. |
| `project` | string | Opcional. |
| `server` | string | Opcional y avanzado. Como en `create_app`. |

## Configurar

### `update_app`

Cambia la configuración de una app. Los cambios de build se aplican en el próximo deploy.

| Parámetro | Tipo | |
| --- | --- | --- |
| `app` | string | Nombre o id. |
| `subdomain` | string | Subdominio nuevo en `olimpia.cc`. |
| `olimpia_domain` | boolean | `false` deja de servir la app en `<subdominio>.olimpia.cc`: los dominios propios siguen funcionando y el subdominio queda reservado. `true` la vuelve a servir. |
| `source` | `upload` \| `github` \| `image` | Cambia el origen de la app. `github` necesita `repo` e `image` necesita `image`. |
| `repo` | string | Para `github`: `owner/name`, para pasar a ese repositorio. |
| `branch` | string | Rama de GitHub. |
| `image` | string | Imagen de Docker. |
| `root_dir`, `dockerfile`, `builder`, `port` | | Como en `create_app`. |
| `watch_paths` | string[] | Rutas desde la raíz del repositorio (`apps/web`, `packages/ui`, `bun.lock`): un push solo redespliega la app si toca alguna. Vacío, redespliega en cada push; con `builder: "acropolis"`, solo cuando cambian los archivos de los que depende la imagen. |
| `auto_deploy` | boolean | Redesplegar en cada push. |
| `confirm` | string | Obligatorio al cambiar `source`, `repo` o `image`: el nombre exacto de la app, después de que la persona aprobó el cambio. |

### `get_env`

Lista las variables de una app. Los valores que parecen secretos (nombres con `SECRET`, `TOKEN`, `KEY`, `PASSWORD`, `AUTH`, o URLs con credenciales) vuelven ocultos salvo con `reveal: true`.

### `set_env`

Agrega, cambia o borra variables, combinándolas con las existentes. Se aplican en el próximo deploy.

| Parámetro | Tipo | |
| --- | --- | --- |
| `set` | object | Variables a agregar o pisar. `PORT` cambia el puerto de la app. |
| `remove` | string[] | Nombres a borrar. |
| `redeploy` | boolean | Desplegar ahora. `false` por defecto. |

### `create_project`

Crea un proyecto.

| Parámetro | Tipo | |
| --- | --- | --- |
| `name` | string | |
| `server` | string | Opcional y avanzado. Sin él, Olimpia elige el servidor solo. Ver [Proyectos](/cuenta/proyectos#servidor). |

### `create_environment`

Crea un ambiente en un proyecto, hasta cinco contando producción. Por defecto copia todas las apps, bases y buckets del ambiente indicado: bases y buckets vacíos con credenciales nuevas, apps con el mismo origen y configuración, variables que apuntan a las copias y un primer deploy.

| Parámetro | Tipo | |
| --- | --- | --- |
| `name` | string | Por ejemplo `staging`. |
| `project` | string | Opcional. El ambiente a copiar, como `tienda` o `tienda.staging`. |
| `copy` | boolean | Copiar los servicios. `true` por defecto; `false` lo crea vacío. |

## Datos

### `create_resource`

Crea una base Postgres, una instancia de Redis, un bucket o un dominio de email. Devuelve los datos de conexión; un dominio de email devuelve además los registros DNS que hay que cargar antes de mandar.

| Parámetro | Tipo | |
| --- | --- | --- |
| `kind` | `postgres` \| `redis` \| `bucket` \| `email` | |
| `name` | string | En `email`, el dominio desde el que se manda (`mail.tuempresa.com`). |
| `connect_to_app` | string | Opcional. Además, carga las variables en esa app. |
| `vector` | boolean | Solo Postgres. `true` la crea con pgvector (`CREATE EXTENSION vector`); por defecto, `false`. No se cambia después. |
| `public` | boolean | Solo Postgres y Redis. `true` la expone a internet por TLS en `*.db.olimpia.cc`; por defecto, `false`: solo la alcanzan las apps de la cuenta. Se cambia después con `set_public_access`. |

### `get_connection`

Datos de conexión: la URL interna para apps en Olimpia, la URL pública si está habilitada, las credenciales S3 de los buckets, y los registros DNS, el estado y la key de un dominio de email (si no está verificado, lo vuelve a revisar en cada llamada). Son secretos.

### `connect_resource`

Carga las variables de conexión en una app y la redespliega.

| Parámetro | Tipo | |
| --- | --- | --- |
| `app` | string | La app que va a usar el recurso. |
| `kind`, `name` | | El recurso. |
| `env_key` | string | Para Postgres y Redis: nombre de la variable (`DATABASE_URL` o `REDIS_URL` por defecto). Si ya existe una variable con ese nombre, la reemplaza. |
| `redeploy` | boolean | `true` por defecto. |

| Recurso | Variables |
| --- | --- |
| Postgres | `DATABASE_URL` |
| Redis | `REDIS_URL` |
| Bucket | `AWS_ENDPOINT_URL_S3`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `BUCKET_NAME` |
| Email | `EMAIL_API_KEY`, `EMAIL_API_URL`, `EMAIL_DOMAIN` |

Si la app ya tiene una variable con el nombre por defecto, las nuevas llevan el nombre del recurso como sufijo (`DATABASE_URL_MAIN`). `env_keys`, en la respuesta, dice qué nombres se usaron.

### `set_public_access`

Expone u oculta una base o un bucket (no aplica a dominios de email). En Postgres y Redis, `public: true` permite conexiones por TLS desde internet; en un bucket, hace que los objetos se puedan leer por URL. Parámetros: `kind`, `name` y `public`. Con `public: true` exige `confirm` con el nombre exacto del recurso, después de que la persona lo aprobó.

### `list_tables`

Lista las tablas y vistas de una base Postgres con cantidad de filas y tamaño. Parámetro: `database`.

### `query_postgres`

Corre SQL como el usuario dueño de la base (no superusuario).

| Parámetro | Tipo | |
| --- | --- | --- |
| `database` | string | Nombre o id de la base. |
| `sql` | string | En lectura, una sola consulta `SELECT`, `WITH` o `VALUES` (hasta 200 filas). En escritura, cualquier sentencia, varias separadas por `;`, en una transacción. |
| `write` | boolean | Modo escritura, con 30 segundos como máximo. |
| `confirm` | string | Obligatorio con `write: true`: el nombre exacto de la base, después de que la persona aprobó el cambio. |

En lectura devuelve las filas como dato no confiable, con `truncated: true` si hay más de 200 filas o pasan de 256 KB. Los errores de Postgres vuelven con su mensaje, también marcado como dato no confiable.

## Backups

### `get_backups`

Configuración de los backups de una base Postgres (destino, frecuencia en UTC y cuántos se conservan) y sus archivos más recientes. `config` vuelve en `null` si no tiene backups configurados. Parámetro: `database`.

### `set_backups`

Programa backups de una base en un bucket de Olimpia o en cualquier S3. Olimpia prueba el acceso al bucket antes de guardar. Si ya estaban configurados, lo que no se pasa queda como estaba: alcanza con `schedule` para cambiar solo la frecuencia.

| Parámetro | Tipo | |
| --- | --- | --- |
| `database` | string | Nombre o id de la base. |
| `bucket` | string | Un bucket de Olimpia del mismo proyecto. No hace falta pasar credenciales. |
| `endpoint` | string | En vez de `bucket`, un S3 externo: `https://host`, sin ruta. |
| `s3_bucket`, `access_key_id`, `secret_access_key` | string | El bucket y la key del S3 externo. Sin `secret_access_key` se mantiene la guardada. |
| `region` | string | Del S3 externo. `auto` por defecto. |
| `schedule` | string | Cron de cinco campos en UTC, con el minuto fijo. `0 3 * * *` por defecto. |
| `keep` | number | Cuántos backups conservar, de 1 a 90. 7 por defecto. |
| `folder` | string | Carpeta dentro del bucket (letras, números, `-` y `_`). `backups` por defecto. |
| `confirm` | string | Obligatorio con `endpoint`: el nombre exacto de la base, después de que la persona aprobó mandar sus backups a ese S3 externo. |

### `run_backup`

Hace un backup ahora con el destino configurado y devuelve los archivos más recientes. Parámetro: `database`.

### `disable_backups`

Deja de hacer backups de una base. Los archivos que ya están en el bucket no se borran. Exige `confirm` con el nombre exacto de la base.

## Dominios

### `add_domain`

Agrega un dominio propio a una app y devuelve los registros DNS que la persona tiene que crear en su proveedor de DNS: un `CNAME` y un `TXT` que prueba que el dominio es suyo. Parámetros: `app`, `domain`.

### `check_domain`

Estado del DNS y del certificado de un dominio.

### `remove_domain`

Quita un dominio de una app.

## Observar

### `get_logs`

Logs de una app o de todas las apps del proyecto (stdout y stderr), con el nivel, el servicio y los atributos de cada línea (JSON, logfmt y access logs). Un error de varias líneas, como un stack trace, llega como una sola entrada. Su contenido es dato no confiable.

| Parámetro | Tipo | |
| --- | --- | --- |
| `app` | string | Nombre o id de la app. Sin `app`, todas las apps vivas del proyecto. |
| `query` | string | Filtro: `level:error`, `service:api`, `http.status_code:>=500`, `duration_ms:>1000`, `http.route:/api/*`, `-healthcheck`, `pattern:<hash>`. Todos los términos tienen que cumplirse. |
| `since` | string | `15m`, `1h` (por defecto), `24h` o `7d`. |
| `around` | string | Fecha RFC 3339: devuelve las líneas de alrededor de ese momento, para ver qué pasó antes y después de un error. |
| `limit` | number | Hasta 500, 100 por defecto. |

Además de las líneas devuelve la cantidad por nivel, los patrones más repetidos (`top_patterns`) y los últimos deploys de la ventana. Varias líneas seguidas del mismo patrón se resumen en una; `pattern:<hash>` las lista y `-pattern:<hash>` las oculta. Se leen las últimas 2000 líneas de cada app: si una app escribe más que eso en la ventana, `covered_from` dice desde cuándo hay datos de esa app.

### `get_analytics`

Visitas reales de una app, medidas en el navegador de sus visitantes en todas las páginas HTML de su subdominio y sus dominios propios: visitas, páginas vistas, una serie en el tiempo, páginas más vistas, orígenes (un nombre vacío es tráfico directo), países (códigos ISO), dispositivos, navegadores y Core Web Vitals al percentil 75 (`lcp_ms`, `inp_ms`, `cls`). Ver [Analytics](/apps/logs-y-metricas#analytics).

| Parámetro | Tipo | |
| --- | --- | --- |
| `app` | string | Nombre o id de la app. |
| `period` | string | `day` (24 horas, por hora), `week` (por defecto, por día) o `month` (30 días, por día). |

## Costos

### `estimate_cost`

Simula el costo mensual aproximado de una configuración a partir de su uso promedio esperado, antes o después de desplegarla. El uso se cobra por lo que se usa de verdad, medido cada minuto: memoria, CPU, disco de Postgres, buckets y emails. Los builds, los certificados, los dominios, los logs y las métricas no se cobran.

| Parámetro | Tipo | |
| --- | --- | --- |
| `memory_gb` | number | Memoria promedio, en GB, que usan todas las apps, Postgres y Redis juntos, sin la caché de archivos. Una app de Node, Bun o Python en reposo usa entre 0,1 y 0,3 GB; un Postgres o un Redis en reposo, entre 0,05 y 0,2 GB. |
| `vcpu` | number | vCPU promedio que usan de verdad (no las reservadas) entre todos. Una app casi sin tráfico usa 0,01 o menos; una ocupada todo el día, entre 0,2 y 1. |
| `disk_gb` | number | GB guardados en bases Postgres. |
| `bucket_gb` | number | GB guardados en buckets. |
| `emails` | number | Destinatarios de email por mes. |

Todos son opcionales y no hace falta `project`. Devuelve cada línea en USD (`lines`, con `kind`, `quantity`, `unit`, `usd_per_unit` y `usd`), el total de uso (`usage_usd`) y lo que cobraría cada plan (`monthly_usd.hobby` y `monthly_usd.pro`): Hobby, USD 5 por mes con USD 5 de uso incluido, y Pro, USD 20 por mes con USD 20, pagando el uso que pase de lo incluido. Es una estimación: el uso real cambia con el tráfico. Ver [Precios y facturación](/cuenta/facturacion).

## Borrar

### `delete_app`

Borra una app con sus deploys y dominios. Irreversible.

### `delete_resource`

Borra una base, una instancia de Redis, un bucket o un dominio de email con todos sus datos. Irreversible.

### `delete_environment`

Borra un ambiente que no sea producción con todas sus apps, bases y buckets. Irreversible. `project` es el ambiente (`tienda.staging`).

Las tres exigen `confirm` con el **nombre exacto** (en `delete_environment`, `<proyecto>.<ambiente>`), después de que la persona confirmó explícitamente.
